# Стенд ШЕКАРЫ в Oracle Cloud

## Управление

- **Ключ администратора** (`SHEKARA_ADMIN_TOKEN` в `~/shekara/deploy/.env`): на сайте кнопка «Ключ администратора»: после ввода появляются пуск/пауза, скорость, режим и сброс.
- **Токен оператора** (`SHEKARA_OPERATOR_TOKEN`): вводится на странице «Оператор». Для жюри его можно указать в заявке.
- Обновить код: снова `deploy\push.ps1`.
- Логи: `ssh ... "cd ~/shekara && docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env logs -f app"`.


## Что защищено

- **Транспорт:** только HTTPS (сертификат Let's Encrypt, HSTS), порт приложения наружу не открыт: в интернет смотрит только Caddy.
- **Доступ:** управление временем: по ключу администратора, вид оператора: по токену (сравнение за постоянное время). Без ключей длиной от 16 символов сборка и приложение не запускаются.
- **Нагрузка:** действия банков: 30 в минуту на IP, все запросы к API: 600 в минуту на IP; тело запроса: до 64 КБ. IP берётся только из заголовка, который ставит Caddy, подставить чужой нельзя.
- **Браузер:** Content-Security-Policy (скрипты и запросы только со своего адреса), запрет фреймов, `nosniff`, `no-referrer`, Permissions-Policy. Фронтенд не использует `innerHTML`: данные с сервера всегда выводятся как текст.
- **Контейнер:** не от root, файловая система только для чтения, без Linux-capabilities, `no-new-privileges`; данные смонтированы только для чтения. Swagger и схема API в публичном режиме не раздаются.
- **Данные:** на стенде только открытый синтетический набор IBM AMLworld: персональных данных нет.

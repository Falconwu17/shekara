## Модель и эксперимент (10 октября, вечер)

**Окружение:** всё на диске D — `.venv` (Python 3.13, torch CPU, PyG, LightGBM, polars, duckdb,
streamlit), кэш pip в `.pip-cache`. Запускать `.venv\Scripts\python -m ...` (Makefile уже так
делает). GPU AMD RX 6600 с PyTorch на Windows не работает — всё считается на CPU (16 потоков).

**Почему основная модель — LightGBM, а не GINE.** Полнобатчевая GINE (`model/gine.py`,
`model/train_rounds.py`) на CPU делала шаг ~7 с и на валидации давала AP ≈ 0,04 с обвалами.
Бустинг на тех же признаках (`model/gbt.py`) — AP ≈ 0,3 за минуту, что позволяет полную сетку
раскрытия на 3 seed. GINE остаётся абляцией к финалу. В материалах: «графовые признаки +
градиентный бустинг; выпуски соседей распространяются по рёбрам локального графа».

**Решения в `model/gbt.py` (все до финального прогона, на валидации):**
- обучение повторяет тест: переводы дня d (d = 2…6) на графе до d, выпуски — ночи d − 1;
  без этого выпуск содержал балл самого обучающего перевода и L3 проигрывал изоляции;
- кросс-фиттинг выпусков для всех ночей (полная модель на ночах ≤ 6 предсказывает «изнутри
  выборки» и сдвигает распределение); контроль `L3_nocf` — полная модель для всех ночей;
- без средних признаков соседей (на общем графе оракула переобучали: AP 0,23 → 0,14);
- признак «банк узла — участник» у всех режимов (иначе флаг «выпуск получен» давал L3 фору);
- без подвыборок в LightGBM: разброс между seed втрое меньше, AP изоляции 0,28 → 0,31;
- вектор выпуска L2/L3 (8 чисел): p «транзитный», max/mean баллов входящих и исходящих,
  доля быстрого вывода, доля новых контрагентов, доля межбанковских исходящих — в [−1, 1].
- оракул в MVP — общий граф переводов участников (полный HI-Small для оракула — Could).

**Результаты (3 seed, со случайными подвыборками, до перехода на детерминированный бустинг):**
- главная метрика (все межбанковские с участником, максимум двух банков): L3 AP 0,301 ± 0,008,
  изоляция 0,279 ± 0,069, оракул 0,236, вид оператора ПС 0,170; F1 0,380 / 0,376 / 0,294 / 0,246;
- **где ШЕКАРА выигрывает:** перевод между участниками, решает банк-отправитель (он не видит
  получателя в чужом банке): L3 AP **0,607 ± 0,017** против изоляции 0,479 ± 0,161, F1 0,618 / 0,516.
  Банк-получатель и так видит своего клиента целиком — там прироста нет (0,37 / 0,42);
- вид оператора ПС (как MITS) устойчиво хуже всех режимов с банковскими данными;
- очередь счетов на завтра («вперёд», `model/node_eval.py`): ночной балл не угадывает
  транзитные счета следующего дня ни в одном режиме (AP ≈ 0,001) — в AMLworld транзитный счёт
  накануне себя не проявляет. Удержание поэтому считать по алерту при зачислении (дневной режим).
- финальная сетка (детерминированный бустинг, все σ L1/L2, R = 2, 3 seed) запущена отдельным
  процессом `experiments/run_all.ps1`; логи — `experiments/logs/grid_*.log` (UTF-16, читать
  PowerShell `Get-Content`), конец — файл `experiments/logs/grid_done.txt`.

**Демо:** паттерн 235 — scatter-gather: 13 дропов сводят деньги на счёт-сборщик `80AE68D00`
в банке 01292; дропы в банках-участниках 006 и 011 переводят сборщику 10.09. Сюжет: выпуск 01292

# ШЕКАРА (SHEKARA)

**Межбанковский поиск сетей дропов без обмена клиентскими данными.** Конкурс АБРК 2026, треки AI for Finance и Digital Banking.

Деньги жертв социальной инженерии проходят через счета-дропы в разных банках, и каждый банк видит одно звено. ШЕКАРА: протокол и графовая модель. Банк передаёт соседу не записи о клиенте, а **одну оценку риска** и только **по ссылке на реальный, уже зачисленный перевод**. Клиентские данные остаются в банке, каждое обращение записывается в журнал, а уровень раскрытия выбирает регулятор.

Полное описание решения: [`docs/SHEKARA.md`](docs/SHEKARA.md). Материалы для подачи: [`docs/submission/`](docs/submission/README.md), там же список того, что отправляется в Оргкомитет: заявка, резюме RU/EN, one-pager, pitch-deck, техническое приложение, демо.

## Результаты (IBM AMLworld HI-Small, 30 банков-участников, 3 запуска)

PR-AUC на межбанковских переводах с участием банков-участников, тестовые дни 8-10.09, 519 положительных переводов.

| Режим | PR-AUC | F1 |
|---|---|---|
| Центральный оператор межбанковских потоков (подход MITS) | 0,251 | 0,357 |
| Общий граф переводов участников | 0,313 | 0,369 |
| Изолированный банк | 0,313 | 0,412 |
| ШЕКАРА L1 (один зашумлённый балл) | 0,320 | 0,409 |
| ШЕКАРА L2 (вектор с шумом) | 0,325 | 0,430 |
| **ШЕКАРА L3 (вектор без шума)** | **0,337** | **0,427** |

- **Собрать данные в одном месте не помогает.** Общий граф всех переводов участников не лучше изолированного банка (0,313 и 0,313). Центральный оператор, который видит только межбанковские потоки, слабее всех: PR-AUC 0,251 против 0,313 у изолированного банка и 0,337 у ШЕКАРЫ. Каскад вкладов: собственный взгляд банка +0,062, сочетание двух моделей +0,005, содержимое оценок соседей +0,019 (не значимо на трёх запусках).
- **Обмен помогает, но пока не доказан статистически.** ШЕКАРА L3 выше изолированного банка во всех трёх запусках (+8% PR-AUC), и прирост даёт именно содержимое выпусков: сочетание двух моделей банка без него почти не отличается от изоляции (0,319). По заранее заданному тесту прирост F1 значим лишь в 1 из 3 запусков.
- **Цена приватности измерена.** Выпуски с шумом (L1, L2) дают немногим больше контроля. Заметная польза есть только у выпуска без шума (L3), у которого нет формальной гарантии ε.
- **Эксперимент проверен на собственные ошибки.** 17.10.2026 найдены и исправлены три: занижены базовые линии (общему графу и оператору не хватало попарных признаков), утечка меток в кросс-фиттинге выпусков, переобучение моделей с выпусками. Поданные 20.10 документы построены на первой версии; сравнение трёх версий: в техническом приложении.
- **Удержание денег.** Если звено длится 3 мин, а аналитик реагирует за 15 мин, деньги остаются на счёте в ≈ 8% звеньев. С временной задержкой исходящих для верхушки очереди (режим H1): в ≈ 31%, при цене меньше одного честного клиента на банк в сутки.
- **Скорость и проверки.** Проверка перевода при зачислении занимает 0,7 мс. Все 22 проверки чек-листа 6.7 пройдены, включая воспроизводимость и нулевой эксперимент на перемешанных метках ([`experiments/results/checks.md`](experiments/results/checks.md)).

Подробные таблицы: в техническом приложении: срезы по сторонам перевода, кривая «раскрытие ↔ качество ↔ ε», парный бутстреп, охват N = 100/200, каскад инцидентов, удержание и задержки.

## Воспроизведение (Windows, CPU, ≈ 2 ч на весь эксперимент)

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

# датасет: Kaggle → ealtman2019/ibm-transactions-for-anti-money-laundering-aml
# файлы HI-Small_Trans.csv и HI-Small_Patterns.txt положить в data\raw\

.venv\Scripts\python -m data.stats        # полные дни, участники (решение уже в data/split_decision.json)
.venv\Scripts\python -m data.split        # базы банков data/processed/banks/*.duckdb
.venv\Scripts\python -m demo.pick_case    # демо-паттерн по правилам без баллов
powershell -ExecutionPolicy Bypass -File experiments\run_full.ps1    # весь эксперимент: сетка × 3 seed, метрики, удержание, каскад, чек-лист 6.7
.venv\Scripts\python -m docs.submission.build ; .venv\Scripts\python -m docs.submission.appendix
.venv\Scripts\python -m docs.submission.resume ; .venv\Scripts\python -m docs.submission.one_pager ; .venv\Scripts\python -m docs.submission.to_docx   # Word для подачи
.venv\Scripts\python -m pytest            # 114 тестов
```

С установленным `make` те же шаги запускаются целями `make stats / data / case / experiment / test`.

## Демо

Веб-стенд: `.venv\Scripts\python -m online.api`, затем `http://localhost:8000/`: сеть банков, кабинет банка, оператор, журнал хаба, итоги эксперимента. Фронтенд без сборки, устройство и правила: в [web/README.md](web/README.md).

```powershell
.venv\Scripts\streamlit run dashboard\app.py          # офлайн-дашборд: Сцена / Банк / Оператор / Эксперимент
.venv\Scripts\python -m online.api --banks 006,011,01292   # API протокола: http://localhost:8000/docs
docker compose up --build                              # то же в контейнерах (API :8000, дашборд :8501)
```

## Публичный стенд

Работающий стенд: **<https://shekara.21restobar.kz>** (Oracle Cloud, бесплатный тариф Always Free). Комплект для выкладки в интернет: [`deploy/`](deploy/): Caddy с автоматическим HTTPS, одна команда настройки сервера и одна команда заливки данных. Пошагово, включая свой домен: [`deploy/README.md`](deploy/README.md).

В публичном режиме стенд сам проигрывает тестовые дни по кругу. Управление временем закрыто ключом администратора, вид оператора: токеном, действия и запросы ограничены по IP. Заголовки CSP и HSTS, контейнер без root и только для чтения; без ключей сервер не запускается.

## Структура

| Папка | Что внутри |
|---|---|
| `protocol/` | ключ перевода `tx_ref`, HMAC пар банков, шлюз need-to-know с квотой и шумом L1-L3, шифрование ответов и выпусков адресату (NaCl), учёт ε, хаб с журналом на хэш-цепочке и подписью Ed25519 |
| `trace/` | инциденты I0-I2, сегменты, дерево оператора; удержание до вывода; каскад |
| `online/` | очередь алертов с бюджетом, HTTP-API, симулятор стенда, итоги для `/v1/results` |
| `web/` | фронтенд стенда: ES-модули без сборки, [устройство](web/README.md) |
| `deploy/` | выкладка в Oracle Cloud: Caddy, compose, скрипты настройки и заливки |
| `data/` | загрузка AMLworld, `make stats`, разбиение на банки, метки, признаки без заглядывания вперёд |
| `model/` | основная модель (`gbt.py`, LightGBM), абляция GINE, проверка при зачислении, сочетание моделей, метрики |
| `demo/`, `dashboard/` | выбор и проигрывание демо-паттерна, дашборд |
| `experiments/` | скрипты прогонов, проверки 6.7, задержки, исследование охвата; `results/`  CSV с результатами |
| `docs/` | решение, источники цифр по РК, похожие работы, материалы для подачи |

## Ограничения

Данные синтетические. В AMLworld нет ID перевода, поэтому ссылка строится из полей. Цепочки в AMLworld медленные: медиана интервала между звеньями ≈ 21 ч на днях обучения и ≈ 11 ч в тестовые дни. Нет канала по телефону, возраста счёта и KYC. В симуляции у всех банков одна модель с общими весами. При полезном шуме формальный ε велик. Подробнее: раздел «Ограничения» в техническом приложении. Следующий шаг: пилот с двумя банками в песочнице НБК / АРРФР.
